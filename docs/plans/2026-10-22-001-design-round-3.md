## 5. Migration

- Applier: `bayan fmt <path>` (5.1a) parses each `.byn`, applies the fixes of every input-form code in order of position, and rewrites the file; it runs again after each 5.1 commit for that commit's codes. Idempotent: a second run changes nothing (test in 5.2b).
- Goldens (`tests/cases`, 435 `.byn`): 413 files have trailing `;` (5.1a); ~273 typed locals, 258 `Type f(`, 165 `void f(`, 119 field declarations (5.1b); 10 `[Attr`, 3 `/*`, 12 `char`, 2 `requires value`, 6 `if !` (unchanged: allowed) (5.1c); 18 `context`, 45 `error enum`, 4 `error set`, 19 one-line unions, 2 `noalloc`/`nosuspend` (5.1d). Expected outputs (`*.ast`, `*.tokens`, `*.diag`, `*.jsonl`, `*.types`) regenerate with `BAYAN_UPDATE=1 dotnet test` and are reviewed. Cases that test the retired `BYN1032` are deleted or re-pointed at the new code; `BYN1005` and `BYN0004` cases are re-checked, not retired (J27). 6 files start a line with `(` (7 lines): check each against the never-join rule by hand.
- `examples/` (7 `.byn`), `selfhost/lexer` (7 files, 3661 lines), `tools/lex-diff/main.byn` (116 lines): `bayan fmt` per 5.1 commit; the selfhost lexer must still build and its `lex-diff` must still match the C# lexer after each step.
- Scaffold templates (`Scaffold.cs:196,206,268,275,284,293`) and `tests/cases/new/*.tree`: hand-edited in 5.1a and 5.1b; `package.byn` template unchanged (`booleans` defaults, J8).
- C#-embedded Bayan: 107 `void main(` programs in 12 test files, hand-edited in 5.1a (`;`) and 5.1b (`main()`); a test helper that runs `fmt` on the string before compiling is not added (J9).
- Docs: step 0 sweeps `docs/` by hand (code fences only); `bayan fmt` can check the fences later if a fence extractor is written (not planned).
- 006 and 007 branches: rebase after 5.1b, run `bayan fmt`, update their spec files (C4, C5).
