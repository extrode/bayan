# BYN3202: duplicate error case in a composition

**Why.** A composed `union error` is flattened: `union error ShipError = CarrierError, StockError` has every case of both sets. When two of them have a case with the same name, `.rejected` in a `fails ShipError` function or a `catch switch` arm could mean either.

**Example.**

```
union error CarrierError {
    timeout
    rejected
}
union error StockError {
    outOfStock
    rejected
}
union error ShipError = CarrierError, StockError
```

Different instantiations of one generic set are not a clash: `union error FormError = ValidationError<Signup>, ValidationError<Address>` is valid, and a `catch switch` matches them by type (`ValidationError<Signup> e => …`). The message names each set with its type arguments: `` `ValidationError<Signup>` and `SignupError` both have a case `invalid` ``.

**Fix.** Rename one of the cases (`carrierRejected`), or compose fewer sets.
