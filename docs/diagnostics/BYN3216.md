# BYN3216: field written from outside its struct

**Message.** "`{0}.{1}` can be written only by `{0}`'s own methods or with `with`: `{0}` {2}"

`{2}` is "has `requires`", "has states" or "is `@sealed`".

**Help.** "add a `ref this` method to `{0}`, or build a new value with `with`"

**What.** Code outside a struct assigns one of its fields, and the struct has a `requires` rule, a `states` block or `@sealed`. Plain data structs allow direct field writes everywhere.

**Why.** Such a struct owns its fields: only its own methods change them, so it can keep its rules and states, and a `@sealed` struct can change its representation without breaking callers. Other code builds a new value instead; for a struct with `requires`, `with` checks the rules again.

**Example.**

```
@sealed
public struct HttpClientOptions {
    i64 timeout
    i32 retries
}

void tune(ref HttpClientOptions options) {
    options.retries = 5
}
```

**Fix.** Build a new value with `with`, or move the write into a `ref this` method of `HttpClientOptions`:

```
void tune(ref HttpClientOptions options) {
    options = options with { retries: 5 }
}
```
