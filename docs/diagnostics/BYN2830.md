# BYN2830: `HashMap` is not supported yet

**Why.** Bayan has one hash map, `Map<K, V>`. It hashes its keys like an unordered map would, and it also keeps insertion order, so iteration is the same on every run and every build. An unordered `HashMap` would iterate in an order that depends on the hash seed, which deterministic output cannot tolerate. `HashMap` is reported once and then read as `Map`, so nothing else is reported for it.

**Example.**

```
struct Counter {
    HashMap<string, i32> counts
}
```

**Fix.** Write `Map` with the same type arguments: `Map<string, i32> counts`. The fix does this; `bayan format` does not apply it, since the type checker reports it.
