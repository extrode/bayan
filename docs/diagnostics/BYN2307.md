# BYN2307: arguments in the wrong order

**No longer reported.** Retired in design round 3 (§15): particles replace the same-type naming rule. Every required parameter besides the object carries a particle, and the call writes it, so a swapped pair is a missing particle (BYN5005), with the missing particle as the fix. The code stays reserved.

**Why (before design round 3).** An argument written as a variable or field named like a parameter (`start`, `tok.start`) said which parameter it was for. When every unnamed argument did that and they didn't line up with the parameters, the call had them swapped.

**Example (before design round 3).**

```
i64 width(i64 start, i64 end) => end - start
width(end, start)
```

**Now.** The second parameter takes a particle, and the call writes it:

```
i64 width(i64 start, until i64 end) => end - start
width(start, until: end)
```
