# BYN1056: `return .x` where `.x` is an error

**Why.** `return` always returns a value and `fail` always leaves with an error (spec §8), so a reader tells the two exits apart by the keyword alone. In a function that fails, `return .x` where the return type has no case `.x` but the `fails` clause does reads as a value and is an error; it is the older spelling and an input form. When the return type has a case `.x`, `return .x` returns that value and no diagnostic is raised.

**Message.** `return .{0}` returns an error; write `fail .{0}`

**Help.** leave with the error: `fail .{0}`

**Example.**

```
union error LookupError {
    missing
}

i64 find(string key) fails LookupError {
    return .missing if key.isEmpty
    return 1
}
```

**Fix.** Write `fail` in place of `return`:

```
i64 find(string key) fails LookupError {
    fail .missing if key.isEmpty
    return 1
}
```

The diagnostic carries a machine-applicable fix. `bayan format` does not apply it: the code is a binder error, not an input form the parser sees.
