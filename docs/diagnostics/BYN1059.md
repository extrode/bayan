# BYN1059: `state x` member lines

**Why.** A struct declares its typestates in one `states { … }` block after its fields, one state per line, each with an optional named payload. Per-line `state x` members are an input form.

**Example.**

```
struct Order {
    i64 total
    state draft
    state paid(i64 payment)
}
```

**Fix.** Gather the states into one block:

```
struct Order {
    i64 total
    states {
        draft
        paid(i64 payment)
    }
}
```

Every `state` line carries the same machine-applicable fix, and `bayan format` applies it: the lines leave their places and the block takes the place of the last one. There is no fix when the struct already has a `states` block (move the state into it by hand), or when a `state` line shares its line with other code or a comment.
