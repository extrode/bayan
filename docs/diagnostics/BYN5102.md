# BYN5102: `bool` state without `is`, `has` or `can`

A lint: it never blocks a build.

**What.** A `bool` property, or a `bool` method with no arguments that is not `ref this`, is named without the `is`, `has` or `can` prefix. Not reported: names starting with `contains`, `equals`, `matches`, `startsWith`, `endsWith` (verbs that ask a question) or `try` (an attempt, tree 4); `ref this` members (an action that reports success, such as `bool advance(ref this)`); fields.

**Why.** A boolean state reads as a question with `is` / `has` / `can` (spec §5.2, [grammar guide](../bayan-grammar.md) tree 3): `if door.isLocked` says what is asked; `if door.locked` could be an action or a copy.

**Example.**

```
struct Door {
    bool open;

    bool locked() => !open;
}
```

**Fix.** Add the prefix (the machine fix renames the declaration to `isX`; rename the callers with it):

```
struct Door {
    bool open;

    bool isLocked() => !open;
}
```

**Where this comes from.** The `is` / `has` / `can` state follows the Arabic attribute (ṣifa), which describes a thing without acting on it. See the [grammar guide](../bayan-grammar.md) §12.
