# BYN8006: `expects` reads untrusted data

**Message.** "`expects` reads `{0}`, which is `Untrusted`; a violation would trap on outside data"

**Help.** "validate `{0}` with a type that has `requires` before the call"

**What.** A function's `expects` clause reads a parameter of type `Untrusted<T>`.

**Why.** A violated `expects` traps in every build mode. Outside data can break any rule, so checking it with `expects` lets whoever sends the data stop the program. Outside data is validated where it enters, with a `requires` type whose construction fails with a `ValidationError` the caller handles.

**Example.**

```
i64 fit(Untrusted<string> name, by i64 limit) expects name.length <= limit {
    return limit
}
```

**Fix.** Validate the value into a type with `requires` before the call, and take that type:

```
type distinct Name = string requires it.length <= 64

i64 fit(Name name, by i64 limit) => limit
```

The diagnostic has no machine-applicable fix.
