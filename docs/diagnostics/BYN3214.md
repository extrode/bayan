# BYN3214: `rest` parameter stored

**Message.** "`{0}` is borrowed for the call and cannot be stored"

**Help.** "copy it first: `{0}.copy()`"

**What.** A `rest` parameter is returned, or stored somewhere that outlives the call: a `ref` or `out` parameter, or a field of `this`.

**Why.** The values of a `rest` tail live in the caller's stack frame for the one call, so passing them allocates nothing. Once the call returns, the slots are reused, and a stored span would point at whatever comes next.

**Example.**

```
ReadOnlySpan<i64> keep(rest ReadOnlySpan<i64> xs) {
    return xs
}
```

**Fix.** Copy the values into a list that owns them. In v0.1, `copy` takes the allocator to copy into:

```
List<i64> keep(ref Arena arena, rest ReadOnlySpan<i64> xs) {
    return xs.copy(to: arena)
}
```

Reading `xs` and binding it to a local inside the function are fine. The diagnostic has no machine-applicable fix.
