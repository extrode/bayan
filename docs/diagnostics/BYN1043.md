# BYN1043: declaration and local binding in the wrong order

**Not reported yet.** Reserved for round-3 step 5.1b, which raises it from the parser.

**Why.** Declarations put the type first (`Sku sku`, `Grams weight(Order order)`); local bindings put the name first (`let w: Grams = 0g`). One code covers both directions, with one message form each. A name-first declaration reads "`{0}: {1}` is an input form; write `{1} {0}`", and a name-first return reads "`{0}(…) -> {1}` is an input form; write `{1} {0}(…)`". A type-first local reads "`{0} {1}` is an input form; write `let {1}: {0}`".

**Example.**

```
f() -> i32 { … }
f(x: i32) { … }
struct P { name: string }
union Event { timeout(after: Millis) }
void run() { Grams w = 0g; }
```

**Fix.** For a declaration, write the type first: `i32 f()`, `f(i32 x)`, `string name`, `timeout(Millis after)`. A missing return type becomes `void`. For a local binding, write `let w: Grams = 0g`; the local gains `let`. A function type used as a field or parameter type is parenthesized so the name follows it: `(Order -> void uses net) onPaid`. The diagnostic carries the rewrite, and `bayan fmt` applies it.
