# BYN5014: unknown word in a member name

A warning: it never blocks a build.

**What.** A word of a member name is not in the checker's built-in word list or in the project dictionary, so the checker cannot tell whether it is a verb, a noun or an adjective. Each word of a name is checked (`upsertRow` → `upsert`, `row`), on all code, public or not.

**Message.** `{0}` is not a known verb or noun

**Help.** add it to `grammar` in package.byn: `verbs: ["{0}"]`, `nouns: ["{0}"]` or `adjectives: ["{0}"]`

**What counts as known.** A word in the built-in list (`src/Bayan.Semantics/Lexicon.cs`; its verbs are also the verbs a help text may start with), a particle, or a word declared in `grammar` in `package.byn`, compared in lowercase. Regular forms of a known word are known too: `-s`, `-es`, `-ies`, `-ed`, `-ing`, `-er`, `-or`, `-est`, `-ly`, with a doubled consonant undone, and `un-` or `re-` before a known word. An irregular form is declared in `forms`. Not checked: math vocabulary (`sqrt`, `log2`, `radians`, …), single letters and digits (`x`, `v2`), names with letters outside ASCII, and typestate states.

**Why.** The grammar rules ([grammar guide](../bayan-grammar.md) §1) depend on the class of each word: a `ref this` member is named with a verb, a property with a noun. A domain word (`upsert`, `sku`, `kyc`) is declared once for the project rather than suppressed member by member.

**Example.**

```
struct Catalog {
    i64 count

    void upsertRow(ref this) {
        count += 1
    }
}
```

**Fix.** Declare the word in `package.byn`:

```
grammar: Grammar {
    verbs: ["upsert"],
}
```

The fix that adds the word to `package.byn` is not offered yet: a fix edits the file of the diagnostic, and this one edits another file (handoff Question 272).

**Where this comes from.** Arabic grammar sorts every word into ism (noun), fiʿl (verb) and ḥarf (particle), and each rule applies to one class. The checker needs the class of a word before it can apply a rule. See the [grammar guide](../bayan-grammar.md) §12.
