# BYN8001: a safety bypass without `because`

**Why.** Some constructs switch off a check the compiler would otherwise make: `@allow`, `@json(expose)`, a call to a member ending in `Unchecked`, and `unsafe`. Each one names its reason in a `because "…"` clause on its line, so a reviewer and `bayan audit` can see why (spec §4.4). An empty reason is rejected too.

**Example.**

```
@allow(unusedValue)
void warm(Cache cache) {
    cache.load()
}
```

**Fix.** Explain the bypass in a `because` clause:

```
@allow(unusedValue) because "warming only fills the cache"
void warm(Cache cache) {
    cache.load()
}
```

There is no automatic fix: the reason is human text. This version reports `@allow`, `@json(expose)` and calls to a member ending in `Unchecked` without a reason, and any empty reason; `unsafe` is checked once `unsafe` blocks parse.
