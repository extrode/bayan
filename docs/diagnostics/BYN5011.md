# BYN5011: `expects` reads one parameter

**Message.** "this `expects` reads only `{0}`; a type with `requires` checks it once"

**Help.** "declare a type with `requires` for `{0}`"

**What.** A function's `expects` clause tests a single parameter and nothing else. This is a warning.

**Why.** A condition on one value is a fact about that value, not about the call. A type with `requires` checks it once, when the value is built, and every function that takes the type can rely on it; an `expects` checks it again at each call and leaves other functions unprotected.

**Example.**

```
i64 percent(i64 value) expects value in 0..=100 {
    return value
}
```

**Fix.** Declare a type that carries the rule, and take it:

```
type distinct Percent = i64 requires it in 0..=100

i64 percent(Percent value) => value.value
```

An `expects` that relates two parameters (`lo <= hi`) is not reported. The diagnostic has no machine-applicable fix.
