# BYN3213: overlapping overloads

**Not reported yet.** v0.1 overloads differ by particle set only, and two with the same particles are reported as BYN2006; the code is reserved for overloads that differ by parameter type.

**Message.** "`{0}` and `{1}` both accept `{2}`"

**Help.** "change a parameter type or particle so the overloads cannot overlap"

**What.** Two overloads that differ only by parameter type accept the same argument through an implicit conversion, as `void f(Grams g)` beside `void f(Kilograms k)` does when `Kilograms` converts to `Grams`.

**Why.** The overload rules are checked at the declaration so that a call never needs ambiguity resolution. Overlapping overloads would make the choice depend on conversion ranking.

**Fix.** Change a parameter type or a particle so that no argument list fits both.
