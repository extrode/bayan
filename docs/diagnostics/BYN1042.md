# BYN1042: a value or modifier on the next line

**Why.** `return`, `break` and `continue` take their operand on the same line, and a postfix `if` or `unless` sits on the line of its statement. A newline ends the statement, so a value or condition left on the next line would otherwise be a separate statement. One code covers both forms: "`{0}` takes its value on the same line" for an operand, and "a postfix `{0}` must be on the line of its statement" for a modifier.

**Example.**

```
i64 f(i64 x) {
    return
        x + 1
}

void g(bool done) {
    stop()
        if done
}
```

**Fix.** Move the value to the line of `return`, or the `if` clause up to the statement's line. The diagnostic carries a machine-applicable fix that joins the lines.
