# BYN7010: `becomes` without `ref this`

**Message.** `{0}` declares `becomes .{1}` but takes `{2}`; a transition needs `ref this`

**Help.** change the receiver of `{0}` to `ref this`

**Why.** A transition only means something to a caller that still holds the value afterwards. A `move this` receiver ends the caller's ownership, and a plain `this` is a copy the caller never sees again, so `becomes` on either would change a state nobody can observe. `move this is .s` and `this is .s` stay valid for methods without `becomes`: they read or consume a value in a known state. A `become` in a method rejected here reports nothing more.

**Example.**

```
struct Order {
    i64 id
    states {
        draft
        paid(i64 payment)
    }
    void pay(move this is .draft, i64 amount) becomes .paid {
        become .paid(amount)
    }
}
```

**Fix.** Take the receiver as `ref this`, keeping its state: `void pay(ref this is .draft, i64 amount) becomes .paid { … }`. The diagnostic carries a machine-applicable fix that replaces `move` (or adds `ref` before a plain `this`). A method that ends the value's life should drop `becomes` instead.
