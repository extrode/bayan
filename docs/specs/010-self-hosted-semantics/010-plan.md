# 010 — Plan
Spec: ./010-spec.md

## Approach

Port `src/Bayan.Semantics/` (about 14,250 lines) method by method into one Bayan module, `selfhost/semantics/`, the way spec 009 ported the parser. The C# output is the reference: every function keeps its C# name in camelCase, its C# order of checks, and a comment at the top of each file names the C# range it ports. The program is `bayan-check`, built by the bootstrap compiler from `selfhost/semantics/`, and checked against the in-process C# front end (`DiagTests`, `TypedDumpTests`) on every `diag/` and `typed/` golden and on generated programs.

The shape of the port, decided here so the parallel wave does not have to:

- **Trees come from `selfhost/parser/` by `import parser`, tokens from `selfhost/lexer/` by `import lexer`.** The 009 harness already proved the import mechanics: imports resolve under the compilation's package root, so from `selfhost/semantics/` both imports resolve only when the package root is `selfhost/`. The test harness builds with `Compilation.Create(sources, packageRoot: <repo>/selfhost)` exactly as `SelfhostParserTests.cs` does; no compiler change is needed. The CLI still cannot set a package root outside a `package.byn` project (Q430), so `bayan build selfhost/semantics/main.byn` does not work; the harness is the documented way to build `bayan-check`. Importing a module loads all its files, so `selfhost/lexer/main.byn` and `selfhost/parser/main.byn` are compiled too; their `main`s are ordinary functions because only the entry module's `main` is the entry (`Compilation.cs`, `file.Module == EntryModule`).
- **The parser becomes a library (T1, behaviour-neutral).** Nothing in `selfhost/parser/` is `public` today (only the lexer is, from 009's T1). The semantics reads the tree, so T1 adds `public` to every node struct, union and enum in `nodes.byn`, and to `Parser`, `Parser.create` and `parseCompilationUnit` in `parser.byn` — the exact set listed in Data / interfaces. A `public` function without `uses` is checked against an empty effect set (`EffectAnalysis.cs`, `fn.Access == Accessibility.Public`), so `Parser.create` and any allocating public helper get `uses alloc` (the clause form is in `run/lambda-uses-provide.byn`). Tree and diagnostic output do not change; L001, L002, L017 and L018 are rerun (R3). The semantics also needs the lexer's render helpers (`wrap`, `display`, `indent`, `applyFix`, `lineNumber`, and the `Widths`/`FixView` support structs), which are private today; T1 makes them `public` so `render.byn` reuses them rather than copying them.
- **One module, one `Diagnostic`, one message table.** The lexer's `Diagnostic` is error-only (no severity, no related spans, no path), which the parser reuses; `bayan check` needs severity (`error`/`warning`), secondary `---` spans and the `--> file:line:col` line. `selfhost/semantics/` defines its own `Diagnostic` struct (severity, code, path, span, message, label, help, fix, related) and its own renderer (`render.byn`), ports `DiagnosticCodes.cs`'s semantic entries (`codes.byn`), and its CLI converts the parser's lexer/parser diagnostics (read from the public `LexResult.diagnostics`) into that struct before one sorted render. The 210 semantic codes (`DiagnosticCodes.cs` BYN2xxx/3xxx/5xxx/6xxx/7xxx/8xxx) become `enum DiagCode` plus `codeText`, `messageFormat` and `severity`; the lexer and parser codes come from their modules.
- **Symbols are arena structs in per-module tables; types are a union.** C# models symbols and types as a class hierarchy with reference identity (`TypeSymbol` subclasses, `StructSymbol`, `FunctionSymbol`, …) and structural equality for constructed types. Bayan has no inheritance, so: each symbol is a `struct` stored in an `Owned<T>` in a per-module `List<T>` table, and symbols reference each other by `(i64 module, i64 index)` pairs; a `Type` is a `union` with one variant per type kind — primitives, `error`/`null`, a type parameter (index), the constructed kinds (`optional`, `span`, `list`, `map`, `owned`, `untrusted`, `array`, `range`, `tuple`, `function`, `result`, `state`, `dynRef`, `textView`, `builtin`, `errorUnion`), and symbol references (`structRef`, `interfaceRef`, `unionRef`, `enumRef`, `errorSetRef`). `displayName`, `typeEquals`, `typeHash` and `typeIsBorrow` are functions over that union; `TypeParameter.Occurs` recurses over it. `Compilation` is a `struct` holding the module list, the diagnostic bag, the builtins and the other tables.
- **The `Binder` and `Compilation` are structs; their C# `partial class` methods become free functions over `ref`.** `Binder` is `partial` across `Binder.cs`, `BinderExpressions.cs`, `BinderCalls.cs`, `BinderStates.cs` and `BinderErrors.cs`; `Compilation` is `partial` across `Compilation.cs` and `Conformance.cs`. A Bayan struct body cannot span files, so `binder.byn` owns `struct Binder` (state and cursor: scopes, held diagnostics, seeds, lambda counts, narrowed locals) and its per-file methods become free functions `bindExpr(ref Binder b, …)` in the file owning their C# range; `loading.byn` owns `struct Compilation` and `declarations.byn`/`declarations2.byn`/`binding.byn` own the declaration and binding passes as `declareFile(ref Compilation c, …)` and so on. The cross-file entry points are fixed in Data / interfaces; every wave file carries a `struct Tn { static … }` stand-in block for the sibling functions it calls but that have not landed, and T22 (integration) removes the stand-ins.
- **The renderer is the full `DiagnosticRenderer`.** `render.byn` ports `Render`/`RenderAll`/`Sort` with severity names, the `--> file:line:col` line (when the compilation loaded more than one file — the rule the `.diag` goldens use for `includePath`, `DiagTests`), related spans as `---` underlines sorted by line, fix markers, and the error cap of 20. It reuses the lexer's now-`public` `wrap`/`display`/`indent`/`applyFix`/`lineNumber` and `escape`, and sorts by `(path, span.start)`.
- **Loading matches the golden harness, not the whole-directory CLI.** The reference the suite compares against is what `DiagTests`/`TypedDumpTests` compute: `Compilation.Create([entry], dir, options)` with `IncludeTests: name ends with ".test.byn"`, a `package.byn` in the entry's directory read only for `name`, `capabilities` (BYN6004) and `grammar` (BYN5xxx), and imports resolved under the entry's directory. `loading.byn` ports exactly that (`ModuleFiles`, `LoadModule`, `ResolveImport`, `Create`) plus a minimal `package.byn` reader for those three fields. The CLI's `FromProject` `src/app/` layout and `FromPath` whole-directory entry are not exercised by any golden; this is recorded as a Question and the plan does not port them (see Risks).
- **The harness mirrors `SelfhostParserTests.cs`.** One lazily built `bayan-check`; a golden theory over `Golden.Cases("diag")` comparing `bayan-check`'s rendered diagnostics with the in-process C# reference written under `tmp/`; a theory over `Golden.Cases("typed")` comparing `bayan-check --types` with `TypedDump.ToJson`; `--codes` cross-checking the message table against `DiagnosticCodes`; the generated-corpus comparison (R6); the 1 MB timing test (R7); L019 and L020 theories with `[Trait("Law", …)]`; `BAYAN_SKIP_TIMING=1`.

Order of work: T1 (skeleton, import mechanics, `Diagnostic`, message table, stubs) lands first, then T2 (symbol/type model) and T3 (bound nodes) land serially because every other file names those types. The wave T4–T21 then runs in four rounds with disjoint files. T22 integrates (the only task after the wave that may touch any `selfhost/semantics/` file). T23–T26 prove and enact the laws, T27 writes the docs. Each wave writer rebases over merged siblings before finishing and names the goldens that already pass; full parity is T22's done-when.

## Data / interfaces

**Diagnostic and bag** (`diagnostics.byn`, T1): `enum Severity { error, warning, note }`; `struct Fix { TextSpan span; string replacement }`; `struct RelatedSpan { TextSpan span; string label }`; `struct Diagnostic { Severity severity; string code; string path; TextSpan span; string message; string label; string help; bool hasFix; Fix fix; List<RelatedSpan> related }`. Bag helpers `void report(ref Bag, DiagCode, string path, TextSpan, by args, string label, string help, Fix? fix)`, `void addRange`, `void removeRepeats` over `struct Bag { List<Diagnostic> items; bool hasErrors }`. `codes.byn` adds `enum DiagCode` in `DiagnosticCodes.cs` order, `string codeText(DiagCode)`, `string messageFormat(DiagCode)`, `Severity severity(DiagCode)`, and the three-argument `format` the lexer already has.

**Symbol tables** (`symbols.byn`, T2): `struct SymRef { i64 module; i64 index }`. `struct Compilation { List<Module> modules; Bag diagnostics; Builtins builtins; … }` (the `Compilation.cs` lines 23–61 fields, minus `DiagnosticBag`, which the bag is). `struct Module { string name; string cName; string directory; List<FileContext> files; List<Owned<StructSymbol>> structs; List<Owned<FunctionSymbol>> functions; List<Owned<ErrorSetSymbol>> errorSets; List<Owned<EnumSymbol>> enums; List<Owned<UnionSymbol>> unions; List<Owned<InterfaceSymbol>> interfaces; List<Owned<ConstSymbol>> constants; List<Owned<TestSymbol>> tests; … }`, with `Map<string,i64>` name→index lookups beside each list. `struct FileContext { i64 module; Tree tree; Map<string,i64> imports; … }` where `Tree` is the parser's `SyntaxTree`-equivalent (`CompilationUnit` plus the source). `Location` is `(i64 file, TextSpan span)`. Each symbol struct carries the C# fields in order; a `List<Owned<T>>` field that points back to its owner carries an index, and a nullable reference is an `i64` sentinel (`-1`). `FunctionSymbol` carries `List<i64> parameters`, `i64 owner`/`i64 interface`, the `FunctionKind`/`BuiltinFunction` enums, and the mutable analysis fields (`body`, `captures`, `isMutating`, …) exactly as C# sets them.

**Types** (`types.byn`, T2): `union Type { primitive(PrimitiveKind) errorType nullType typeParam(i64) optional(Owned<Type>) span(Owned<Type>, bool readOnly) textView(TextViewKind) dynRef(SymRef, bool readOnly) list(Owned<Type>) map(Owned<Type>, Owned<Type>) owned(Owned<Type>) untrusted(Owned<Type>) array(Owned<Type>, i64) range(Owned<Type>) tuple(Owned<TupleType>) function(Owned<FunctionType>) result(Owned<Type>, Owned<Type>) state(SymRef, List<i64> states) builtin(BuiltinKind) errorUnion(List<SymRef>, List<i64> excluded) structRef(SymRef) interfaceRef(SymRef) unionRef(SymRef) enumRef(SymRef) errorSetRef(SymRef) }`, with `string displayName(Type)`, `bool typeEquals(Type, Type)`, `i64 typeHash(Type)`, `bool typeIsBorrow(Type)`, `bool typeOccurs(Type, i64 tpIndex)`, and the primitive singletons as an `enum PrimitiveKind` plus a `byName` `switch`. `TupleType`, `FunctionType` are `struct`s. Cross-file entry points fixed by T2: `string displayName(Type)`, `bool typeEquals(Type, Type)`, `bool typeIsBorrow(Type)`, `bool typeOccurs(Type, i64 tpIndex)`.

**Bound tree** (`boundnodes.byn`, T3): `union BoundExpr { literal(Owned<BoundLiteral>) symbolLiteral(…) default(…) local(…) this(…) field(…) tupleElement(…) call(…) builtinCall(…) unary(…) binary(…) conversion(…) tryFrom(…) conditional(…) coalesce(…) structLiteral(…) with(…) tuple(…) collection(…) spread(…) index(…) slice(…) range(…) is(…) switchExpr(…) interpolated(…) move(…) try(…) catch(…) jump(…) blockExpr(…) errorVariant(…) enumMember(…) unionNew(…) enumValues(…) staticArray(…) stackalloc(…) errorExpr(…) typeRef(…) moduleRef(…) lambda(…) functionRef(…) unionField(…) errorField(…) }`, likewise `union BoundStmt` and `union BoundPattern` over the records in `BoundNodes.cs`, plus `BoundTree.children`/`descendants` and the `BuiltinMembers.property`/`method` tables as `switch` functions. Each node carries `span`, `type` (a `Type`) and the C# children in order; a nullable C# child is an optional (`i64` sentinel for symbols, `-1` for absent), and child lists are `List<…>`.

**Cross-file entry points** (fixed by T1 as stubs; one per owning file): `CompilationUnit` and `Parser` come from the parser. `Bag`/`Diagnostic`/`report` from `diagnostics.byn`; `codeText`/`messageFormat`/`severity` from `codes.byn`. `Type displayName(Type)` etc. from `types.byn`. `BoundExpr bindExpr(ref Binder b, Expr e, Type? expected)`, `BoundStmt bindStatement(ref Binder b, Stmt s, …)`, `BoundPattern bindPattern(ref Binder b, Pattern p, Type input)`, `Type resolveType(ref Binder b, TypeSyntax t)`, `BoundExpr convert(ref Binder b, BoundExpr v, Type target, TextSpan span, bool argument, bool constrains)`, `void report(ref Binder b, DiagCode code, TextSpan span, by args, string label, string help, Fix? fix)` (binder files); `void declareFile(ref Compilation c, i64 file)` and `void bindAll(ref Compilation c)` (compilation files); `void analyze(ref Compilation c, i64 fn)` for flow/effects/ownership/regions; `void checkMembers(ref Compilation c, i64 structIndex)` (naming). Every other function is private to its file's area and named after its C# method.

**CLI** (`main.byn`, T20): `bayan-check [<path>]` loads the file as single entry with imports under its directory, renders diagnostics (sorted, `includePath` when more than one file loaded), exits 0 or 1; `bayan-check --types <path>` prints the typed dump or nothing on errors; `--many <dir>` runs each `*.byn` in a fresh arena with `== <name>` headers for L020 and the generator; `--time <path>` prints the nanoseconds for parse + check + dump; `--codes` prints `code\tmessage` for every `DiagCode`. Usage and missing-file exits follow the lexer's constants.

**Harness** (`SelfhostSemanticsTests.cs`, T20): `Built` = `Lazy<string>` building `Compilation.Create(selfhost/semantics/*.byn, packageRoot: selfhost/)` in fast mode; `DiagGolden(name)` over `Golden.Cases("diag")`, reference `DiagnosticRenderer.RenderAll(Compilation.Create([Golden.Load(path)], dir, new CompilationOptions(IncludeTests: endsWith(".test.byn"), Capabilities, PackageName)).Diagnostics.Items, includePath: package)` written under `tmp/semantics-ref/`; `TypedGolden(name)` over `Golden.Cases("typed")` vs `TypedDump.ToJson`; `CodesMatchDiagnosticCodes`; `GeneratedSeedsAgree` (R6); `OneMegabyteWithinTenTimes` (R7, median of 5); `[Trait("Law","L019")]` equality including exit codes; `[Trait("Law","L020")]` exit 0/1 and no panic.

## Risks & mitigations

- **The symbol/type model is the largest single design risk (T2, Q525–Q529).** The class hierarchy becomes per-module `List<Owned<T>>` tables with index references and a `Type` union. `run/owned-expr.byn` proves a recursive union through `Owned<T>`, and `run/owned-list.byn` proves `List<Owned<T>>`; the parser's tree already uses both. Fallback if cyclic `Owned` symbol references are rejected: symbols become flat `List<T>` arenas (values, not `Owned`) with every cross-reference an `i64` index, and the wave reaches them through accessors. T2 records which shape shipped.
- **`partial class Binder`/`Compilation` cannot span files (T7–T14, Q550–Q589).** The struct holds state in one file; the methods become free functions over `ref`. The `struct Tn { static … }` stand-in block in each wave file gives every cross-file function a fixed signature (Data / interfaces), so writers call siblings by name before they land; T22 replaces the stand-ins with the real functions and the test files' `[Fact(Skip = "T<integration> enables …")]` cases are unskipped.
- **Cross-module visibility forces parser and lexer edits (T1, Q520–Q524).** `public` on the parser's tree is required (BYN2005 otherwise), and `public` turns on effect checking, so allocating functions need `uses alloc`. If the cascade reaches something that cannot be expressed, T1 stops and records the exact diagnostic; a compiler fix with a test is in scope per R8, and the semantics port settles any package-wide-visibility question the same way 009 raised it.
- **`bayan check`'s literal CLI behaviour differs from the goldens (T20, Q615).** `CliApp.Compile` loads a single file's whole directory (`FromPath`, `wholeDirectory: true`) and always renders with `includePath: true`, while the binding goldens (`DiagTests`) compile the single entry with imports and set `includePath` only for multi-file cases. The plan ports the golden's behaviour (R5's "compares with `bayan check`" reads as the in-process front end the goldens are made from). If the spec meant the literal CLI, T20 is where that is settled; the whole-directory entry and the `src/app/` project layout are not ported until then.
- **Diagnostic ordering, dedup and the error cap (T19–T20, Q610–Q614).** `Sort` is by `(path, span.start)` (`DiagnosticRenderer.Sort`); the bag's `RemoveRepeats` drops a diagnostic that repeats an earlier code+file+span+message (needed for test cases that bind the same body once per case, `Compilation.cs` line 112). The renderer's error cap of 20 and `--all` are ported for completeness even though the golden corpus stays under it.
- **The integer-literal two-pass and `it` (T11–T13, Q570–Q584).** `Binder.Hold`/`Release` holds a first pass's diagnostics and seeds non-`i32` integer `var`s for a second bind; the port keeps the same shape with the held bag as a `Bag?` on `struct Binder`. If the `by (ref Binder -> Expr) f`-style callback the C# `Holding<T>(Func<T>)` implies cannot be expressed, the sites inline the save/restore around a direct call, as 009 did for `try/finally`.
- **The renderer is richer than the lexer's (T19, Q610).** It needs severity, related spans and path lines the lexer's `render` omits; the plan reuses the lexer's now-`public` helpers and adds only those parts. `Related` spans appear in semantics diagnostics (`BinderCalls` uses them for argument notes); the parser's `Related` is empty, so converting parser diagnostics to the new struct loses nothing.
- **Type equality and hashing on the hot path (T2, T21, Q529/Q622).** `Map` with composite keys needs `typeHash`/`typeEquals`; `TypeParameter.Occurs` and `displayName` run constantly. Costs mirror C# (`ConstructedType.Key`). If `bayan-check` exceeds 10× on the 1 MB input, T21 records the breakdown from `--time` and the cause (expected suspects: `Type` union hashing, `Map` lookups, `List<Owned<Symbol>>` growth) and fixes it only inside `selfhost/semantics/`.
- **`RegionAnalysis` is the largest single file (T17, Q600).** 882 C# lines port to about 1,200 Bayan; if it does not fit one writer's ~80 turns it splits into `regionanalysis.byn` + `regionanalysis2.byn` along the borrow/loan boundary, with the loan helpers' signatures fixed in Data / interfaces.
- **Unbounded recursion in both checkers (T25, Q629).** Deep input overflows the stack in C# and in the port alike. The generator caps nesting depth; L020's proof notes state the exclusion and the Question proposes a shared limit for a later spec.
- **L020 may be false of the C# reference (T25, Q631).** A diagnostic span outside its file, or a panic on a corrupted input in C#, would make the law false as stated; the port keeps matching C# (L019 and the non-goal win), the input goes to `work/todo.md` and the proof notes, and the law's statement is left as proposed until the C# fix lands; enacting is then T26's call to skip and say so.
- **Writers cannot see full parity until the wave merges (all wave tasks).** Each wave task's done-when is a complete method-for-method port that builds against siblings' stand-ins; the writer rebases over merged siblings and names the goldens that already pass; T22 owns the last mile and may edit any file.
