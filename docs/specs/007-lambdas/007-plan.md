## Approach

**A function type is a structural `ConstructedType`; a function value is a (code, environment) pair that borrows the frame that made it.** `FunctionType(Parameters, Return, Fails)` joins `OptionalType`, `SpanType`, `TupleType` and the rest in `Types.cs` (ConstructedType at :162 gives structural `Equals`/`GetHashCode` through `Key`), with `IsBorrow => true` (Types.cs:35, as `SpanType` at :183). That one bit buys R10 for free: region analysis already forbids storing a borrow in a field (BYN3001), returning it (BYN3003, RegionAnalysis.cs:449) or outliving its source (BYN3002, :436), and reports modification while borrowed (BYN3004, :506). In C the value is `struct { R (*fn)(void* env, A, B[, R* out]); void* env; }`, emitted through `Named`/`EmitTypes` like a tuple (CEmitter.cs:254, :262-306); a call through it is `f.fn(f.env, …)`.

**Lambdas are lifted to ordinary `FunctionSymbol`s at bind time; captures are tuple fields.** A lambda binds to a synthesized `FunctionSymbol { Kind: FunctionKind.Lambda, Module, File, Parameters from the expected type, ReturnType, ErrorSets, Fails }` appended to `ModuleSymbol.AllFunctions` (Symbols.cs:56), so lowering (Lowerer.cs:19), the analyses loop (Compilation.cs:914-932), `bayan types` (TypedDump.cs:27) and emission (CEmitter.cs:61) see it with no new loop. The body is bound inline by the enclosing binder with `_fn` switched to the lambda symbol and a nested scope, so `return` targets the lambda and outer names resolve through `_scope.Lookup` (BinderExpressions.cs:408); a resolved outer local is recorded as a capture. The bound expression `BoundLambda(Syntax, Lambda, Captures: BoundLocal[], Type)` lists one `BoundLocal` read per capture as its children (BoundTree.cs:7), so flow analysis sees a read, ownership analysis sees a copy (BYN2780 for `unique`, OwnershipAnalysis.cs:407) and region analysis sees a value derived from every capture's root (RegionAnalysis.cs:517, :537), with no lambda-specific rule in any of the three. Lowering spills the captures into a temp of type `TupleType(captures)` (Lowerer.cs:88 `NewTemp`, Types.cs:271) and builds the pair from the lifted function's name and `&temp`; inside the lifted function the emitter maps each captured `LocalSymbol` to `((tuple*)env)->itemN` through `_names` (CEmitter.cs:775-778), so the body reads captures as if they were locals. Tuples already have C definitions (:304), keys (:250) and equality, so no new type emission is needed for environments. The temp lives for the whole enclosing frame (locals are declared at function top, :806-809), which is longer than any borrow of the lambda can be (R10). Rationale over monomorphizing the callee per lambda (spec §3.16's "inlined"): one calling convention serves named functions, non-capturing and capturing lambdas alike, the generics machinery is untouched, and inlining stays a later optimisation that changes no observable behaviour (L013 pins that).

**Named functions as values reuse the `BoundMethodGroup` hook.** `Binder.cs:959-966` already recognises a module function named as a value and renders its signature for a mismatch. Conversion to a function type moves that check into `Conversions.Implicit` (Conversions.cs:11) as `ConversionKind.ToFunction` over a `BoundMethodGroup { Receiver: null, Function: { Kind: Function, !IsGeneric } }`, producing `BoundFunctionRef(Function, Type)`; the emitter wraps the function in a per-function thunk with the `void* env` first parameter. `Panic.onPanic` keeps its path untouched (Q114).

**Calls through a value are `BoundCall`s of a synthesized invoke symbol.** Per `FunctionType` the compilation holds one `FunctionSymbol { Kind: FunctionKind.Invoke, Parameters: unnamed, ReturnType, ErrorSets, Fails }`; `BindCall` (BinderCalls.cs:24) adds a case for a callee whose type is a `FunctionType` and goes through `BindFunctionCall` (:73) with the value as `Receiver`. Everything downstream that keys on `BoundCall` keeps working: the `fails` check and `try` insertion (:100-105), `ErrorFlow` (ErrorFlow.cs:15, :18), the try/catch lowering, and `BoundTree.Children`. Two places must learn that a receiver without `HasThis` is the callee value: `Lowerer.CallParts` (Lowerer.cs:1124 drops the receiver unless `HasThis`) and `CEmitter.Call` (CEmitter.cs:1175).

**`it` is a binder decision, not a parser one.** The parser never sees `it`; `BindArgumentValue` (BinderCalls.cs:351) checks, when the parameter type is a one-parameter `FunctionType` and the argument is not a `LambdaExpr`, whether the argument's syntax mentions the name `it` outside a nested `LambdaExpr`, and if so binds it as a lambda whose one parameter is named `it`. A depth counter makes a second such argument inside the first BYN2029. `.name` with an expected function type is caught in `BindTargetMember` (BinderCalls.cs:26 passes `expected`) and reported as BYN2823.

## Risks & mitigations

- **Two-pass binding of bodies** (Compilation.cs:1103-1133): the first `BindBody` lifts lambdas into `AllFunctions` and the second lifts them again. Mitigation: record lambdas lifted during a pass in the same `pass` tuple as instances and remove them at :1125; a golden with a lambda inside a function that has an untyped-literal `var` (the rollback trigger, `run/generics-var-literal-rollback.byn`'s shape) proves it.
- **`ScanType` speculation** (Parser.cs:687): `=>` after a type at statement start changes which statements are declarations; `x => x + 1;` as an expression statement starts with an identifier and is not a declaration today either (a name followed by `=>` is not a type-then-name shape), but `(a, b) => …` at statement start would scan as a tuple type. Mitigation: `ScanType`'s paren path returns -1 when the closing `)` is followed by `=>` and the elements are bare names; parse goldens for both statement shapes.
- **`=>` ambiguity in `fails`** (`() => T fails A, B`): the error-set list ends at the first token that cannot continue a name list, which is also how `ParseFunction` ends its `fails` (:485-495); a function type in a parameter list is followed by `,`, a name or `)`, so the comma rule needs the same lookahead `ParseParams` uses (`fails A, B name` versus `fails A, B, i32 x`). Mitigation: inside a parameter list the `fails` of a function type takes one error set unless parenthesised (`fails (A, B)`); recorded as Q121.
- **Tuple of one capture**: `TupleType` with a single field is never produced by the parser; the symbol and emitter accept any count (Types.cs:271, CEmitter.cs:304-305), but `Key` "tup1_x" and equality helpers were never exercised. Mitigation: T7 adds a run golden with exactly one capture; if anything balks, the environment pads with a `bool`.
- **Environment temp per evaluation**: a lambda created in a loop reuses one temp, so a lambda value from iteration *i* held past iteration *i+1* would see new captures. Region analysis forbids that only if the lambda value borrows the temp. Mitigation: the lowered `LFunctionValue` reads the env temp as a `BoundLocal`, and `FunctionType.IsBorrow` plus the loop-scope region rules make a function value that escapes its iteration BYN3002; L014's table includes this shape.
- **Capturing a narrowed optional** (BinderExpressions.cs:412-413 wraps a non-null `let` in a `Narrow` conversion): the capture must copy the narrowed value, not the optional. Mitigation: captures record the `BoundLocal` read exactly as `BindName` produced it; the tuple field has the narrowed type.
- **`-Wall -Werror` on pre-existing emission**: as in 006; the first law proof to land cleans local warnings in `CEmitter.cs` and records any narrowing in its proof notes.
- **`it` detection by syntax walk** runs on every argument to a function-typed parameter; it is linear in the argument's size and only when the parameter type is a one-parameter function type, so no measurable cost. A `NameExpr` named `it` that resolves to a user local named `it` is still rewritten; Q117 records that a local named `it` cannot be passed bare to such a parameter (write a lambda with a named parameter instead).
- **Lambdas inside generic templates** are bound once on the template (ownership runs there) and once per instance (flow, regions); the lifted symbol must exist per instance with substituted types. Mitigation: the lambda is lifted during the binding that creates it, so each instance's `BindBody` creates its own; `FunctionName` adds the instance's `TypeArgs` (CEmitter.cs:181).
- **Goldens of `.ast` dumps**: new node kinds change no existing dump; `parse/` additions only.

## Self-hosting gaps

What spec 009's port must work around, given this subset:
- No stored callbacks: a visitor table, a `Dictionary<TokenKind, Func<…>>` or a parser rule table becomes a `switch` or a function-typed parameter threaded through the calls.
- No function-typed fields or return types: a "parse this then that" combinator style is out; helpers take their callback as a parameter each call.
- No `ref` captures: a lambda that must update a counter takes it as a `ref` parameter of the called function instead, or the loop is written out.
- No built-in `where`/`select`/`sort(by:)`: the port writes `any`, `indexWhere`, `sortBy` over spans once in its own prelude.
- No generic aliases: `type Predicate<T>` is spelled per type (`type TokenPred = Token => bool;`).
- No lambdas in `const` initializers and no function values in `static` data: keyword tables stay arrays of names, not of handlers.
- No `this` capture: a method that passes a lambda copies the fields it needs into `let` values first.
