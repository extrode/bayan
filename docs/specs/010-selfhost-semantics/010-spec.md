## Problem

The handoff's "Road to self-hosting" row 010 ports semantics: the binder, flow, ownership and region analyses, as a Bayan program under `selfhost/`, checked against every `diag/` golden and, through spec 004's typed dump (`bayan types`, `docs/typed-dump.md`), against a binder-equivalence law: C# and Bayan typed dumps identical on every input, proven like L001. Spec 009 gives a Bayan tree for every input. Nothing in Bayan binds one today.

`src/Bayan.Semantics` is about 9,400 lines of C# at `8322db9`, before round 3 adds typestate (5.3c), effects (5.3d) and particles (5.3e): `Compilation.cs` (1,306: loading, imports, declaration, generics and their instantiation worklist, the two-pass integer-literal inference of `BindFunction`, error-set inference, mutation and `requires` checks), `Binder.cs` (1,057, statements), `BinderExpressions.cs` (1,587), `BinderCalls.cs` (1,405: calls, inference, `try`/`catch`, switch, patterns, exhaustiveness, assignment), `RegionAnalysis.cs` (590), `Symbols.cs` (490), `OwnershipAnalysis.cs` (437), `Types.cs` (371), `FlowAnalysis.cs` (325), `BoundNodes.cs` (306), `TypeResolver.cs` (273), `Builtins.cs` (207), `Naming.cs` (187), `ConstantFolding.cs` (182), and seven files under 115 lines. It reports about 170 codes in BYN2000–5199, many with labels, helps, fixes, related spans and warnings, which the lexer port's `Diagnostic` (`selfhost/lexer/diagnostics.byn:74`) cannot carry. Its symbols are reference-identity classes kept in 82 `Dictionary` and `HashSet` sites; a Bayan port has no object identity and iterates `Map` in insertion order (L003), so any C# output that depends on hash order would differ. Two C# gaps also stand in the way of a law "on every input": nothing bounds how deep generic instantiation nests (`InstantiateFunction`, `Compilation.cs:995-1019`, enqueues every new instance), and the binder recurses once per operand of a left-nested binary chain, which the parser builds in a loop that BYN1070 does not count.

## Goals

- `bayan-check`, written in Bayan in round-3 syntax and built by the C# compiler, prints exactly the typed dump and the rendered diagnostics the C# front end produces, on every `diag/` and `typed/` golden and on every other input.
- The Bayan binder binds the self-hosted compiler's own sources (`selfhost/lexer`, `selfhost/parser`, `selfhost/semantics`) with the same result as the C# binder, as an early milestone.
- Neither binder crashes or runs without bound on any input.
- A change to either binder that makes them disagree fails the normal test run and names the input and the first differing line.
- The bound tree and symbol tables are data spec 011 can lower: ids, not pointers.

## Non-goals

- Replacing the C# front end inside the compiler. The Bayan binder is a second implementation, checked against the first, until spec 012.
- Lowering, the C emitter, `bayan build` and `bayan run` (specs 011, 012).
- New checks, better messages or changed recovery. The port is 1:1 by method; a change lands in `src/Bayan.Semantics` first and is ported after (Q157).
- A new typed dump version, expression types in the dump, or a change to `bayan types` (Q153).
- Package manifests (`package.byn`), `manifest/` goldens, `--diagnostics json`, `bayan audit` and `bayan features` (C# CLI only, handoff "Finish line").
- `CompilationOptions.Library` and `SkipOwnershipCheck` (Q160).
- `Owned<T>` symbol graphs, `type distinct` ids and round-3 §9 typed indices for the port's own data (as 009 Q144).

## User stories

- As the author of the emitter port, I want the Bayan binder's results to equal the C# binder's on every input, so that a disagreement in spec 011 is never a binder bug in disguise.
- As the port author, I want each pass ported as one Bayan file beside its C# file, so that a reviewer reads them side by side.
- As a compiler developer, I want a failing test that names the input and the first differing line whenever the binders disagree, so that the two cannot drift.
- As the port author, I want the self-hosted sources to bind early, so that the subset the compiler needs is proven before the long tail of diagnostics.
- As anyone fuzzing `bayan check`, I want runaway generic instantiation and very deep expressions to be diagnostics, not hangs or stack overflows.

## Requirements

- R1 Program. `selfhost/semantics/main.byn` is `bayan-check`: `bayan-check <path>` compiles a `.byn` file, or a package directory whose `main.byn` is the entry (as `DiagTests` does, `tests/Bayan.Tests/DiagTests.cs:17-23`), with tests included when the name ends in `.test.byn`, and prints the typed dump (`docs/typed-dump.md`, version 1) followed by a blank line and the diagnostics rendered as `DiagnosticRenderer.RenderAll` does, with paths when the input is a package. It exits 0 when no diagnostic is an error, else 1. `bayan-check -` reads one file from stdin as `<stdin>`. `bayan-check --many <dir>` prints `== <name>` and that output for every input in `<dir>` in name order. `bayan-check --time <path>` prints only the nanoseconds spent lexing, parsing and checking. Exit 2 on a usage error, 4 when an input cannot be read, as `bayan-lex` and `bayan-parse`.
- R2 Source. Round-3 syntax (spec and GRAMMAR on this branch): no semicolons, name-first bindings and fields, `->` returns, `@` attributes, particles, `length` for sizes; `bayan fmt --check selfhost/semantics` changes nothing. One module made of the lexer's and parser's library files (every `selfhost/lexer/*.byn` and `selfhost/parser/*.byn` except `main.byn`) and `selfhost/semantics/*.byn`, assembled by the test harness (Q154).
- R3 Coverage. The port binds and reports exactly what `src/Bayan.Semantics` does after the round-3 steps in the Depends-on line: module loading and imports, declaration and naming checks, attributes and `@cases`, type resolution, builtins and builtin members, constant folding, conversions, statements, expressions, calls with argument names and particles, generic inference and instantiation, the two-pass integer-literal inference, error-set inference, mutation and `requires` checks, flow, ownership, regions, typestate, effects, the panic-handler check and the lints, in the same pass order as `BindAll` (`Compilation.cs:886-941`). The target is every `diag/` golden (Q152).
- R4 Data. Symbols and types are entries in pools addressed by single-field id structs (`TypeId { index: i32 }`, `FunctionId`, `LocalId`, `ModuleId`, …). Types are interned: a structural `TypeKey` maps to one `TypeId` through a `Map<TypeKey, TypeId>` (008 R5), so type equality is id equality, as reference equality is in C#. Scopes are `List<Map<Symbol, LocalId>>` searched innermost first; members are `Map<MemberKey, SymbolRef>` with `MemberKey { owner: TypeId, name: Symbol }`; generic instances are `Map<(SymbolRef, TypeListId), SymbolRef>` with interned type-argument lists. Side tables are keyed by 009's node ids (`Map<ExprId, BoundExprId>`). The bound tree mirrors `BoundNodes.cs` 1:1 as pools of `{ span, type, kind }` structs. No struct holds a pointer, an `Owned<T>` or a borrow (Q155).
- R5 Language use. Interface constraints (006 R4) for the pool and table helpers shared across symbol kinds; `for x in pool.items` (built-in `List<T>` iteration); function-type parameters and `it` lambdas (007) for searches over scopes and members (`indexWhere(members, by: it.name == name)`, the shape of 007 R15); no lambda captures `this` or a `var` and no function value is stored in a field (007 R8, R10).
- R6 Order. Every diagnostic and every dump entry comes out in the same order as in C#. Wherever the C# front end iterates a `Dictionary` or `HashSet` and the order can reach a diagnostic, a related span or the dump, T1 makes the C# order explicit (insertion or sorted) before the port, so the Bayan port can match it with insertion-ordered `Map` (L003) (Q156).
- R7 Diagnostics. The lexer port's `Diagnostic` gains severity, related spans with labels, and the source file, and its renderer prints them as `DiagnosticRenderer` does (warnings, secondary labels, `includePath`); L001 and L017 are re-run after the change (Q161). Every semantic diagnostic has the same code, severity, source, span, message, label, help, fix and related spans in the Bayan port, in the same order. The message templates live in one table in `selfhost/semantics/`, and a test checks that every `BYN2xxx`–`BYN9xxx` constant in `DiagnosticCodes.cs` has an entry.
- R8 Bounds. Both binders bound generic instantiation and expression depth identically. If T1 shows that the C# compiler instantiates without bound, both report BYN2840 when an instance would nest more than 64 instantiations deep and stop instantiating from that site (Q158). If T1 shows that the C# binder overflows its stack on a left-nested chain of 100,000 binary operands, both report BYN2841 at the operand that opens level 4,097 and do not bind below it (Q159). A bound T1 shows is unneeded is not added, and its code stays reserved.
- R9 Checks in the suite. The normal test run builds `bayan-check` once per test process (cached as `bayan-lex` is) and compares its output with the C# reference (`TypedDump.ToJson(c)` + `"\n"` + `DiagnosticRenderer.RenderAll(c.Diagnostics.Items, includePath)`, computed in process) for: every `tests/cases/diag/` case, every `tests/cases/typed/` case (whose dump must also equal the `.types` golden), and every `.byn` under `tests/cases/run`, `tests/cases/parse`, `examples`, `selfhost` and `tools`. A disagreement fails the run and names the input and the first differing line. Until R3's target is reached, the cases not yet passing are listed in one pending file; a listed case that passes fails the run, so the list only shrinks.
- R10 Corpus. On a generated corpus of at least 10,000 inputs (Q162), `bayan-check --many` prints exactly the C# reference for each, never panics, and finishes each input within the test's timeout; at least 80% of the inputs parse without error, so the corpus exercises binding and not only parse recovery.
- R11 Speed. Checking the self-hosted sources (R2's module) with `bayan-check` built in `fast` mode takes no more than 10 times as long as the C# front end on the same machine (median of 5; `BAYAN_SKIP_TIMING=1` skips) (Q163).
- R12 Diagnostic docs. BYN2840 and BYN2841, if allocated, each have a `docs/diagnostics/` page, a `diag/` golden and a verb-first help (spec 005 R15).
- R13 Self-hosting reach. `bayan-check` on R2's module (the lexer, parser and semantics sources together) prints the C# reference, which has no error, so the binder binds itself; this has its own test and is reached before the full `diag/` set (T16).
- R14 Internal errors. An input on which the C# front end throws (for example the instantiation `internal error` at `Compilation.cs:934-936`) fails the run as a C# bug; it is fixed in C# with its own golden, not ported (Q164).

## Acceptance criteria

- Given `tests/cases/typed/constrained-i64.byn`, when `bayan-check` runs on it, then its dump equals `constrained-i64.types`, no diagnostics follow, and it exits 0.
- Given every `tests/cases/diag/` case, file or package, then `bayan-check`'s output equals the C# reference byte for byte, and the pending list is empty.
- Given a `diag/` case that reports a warning (BYN2712, a `_` arm over a local union) and one with a related span, then the Bayan rendering shows the same severity word, carets, secondary labels and help as their `.diag` goldens.
- Given a package case such as `tests/cases/diag/import-cycle/`, then the Bayan output renders paths as `DiagTests` does.
- Given `let x = 1` on stdin, when `bayan-check -` runs, then the output equals the C# reference for a file with that text.
- Given the module of R2, then `bayan-check` prints the C# reference, every function's bindings agree, and there is no diagnostic.
- Given a generic `grow<T>(x: T)` whose body declares `let next: List<T> = []` and calls `grow(next)`, then either both binders report BYN2840 once at the inner call, or T1 has recorded that the C# compiler already stops with an existing diagnostic and both report that.
- Given a chain of 100,000 `1 +` terms, then neither process crashes, and both print the same output.
- Given the 10,000-input corpus, then every output agrees, stderr has no `panic:`, and at least 8,000 inputs parse without error.
- Given a `BYN2xxx` code in `DiagnosticCodes.cs` with no entry in the Bayan message table, then the table test fails naming the code.
- Given a C# change that makes `Dictionary` iteration order reach a diagnostic, then the order test of T1 fails naming the site.

## Law candidates

- L018 (property, proven like L001 and L017): for every input in the binder corpus (every `diag/` and `typed/` case, every `.byn` in the repository, and the generated corpus of R10), `bayan-check` and the C# front end produce byte-identical typed dumps and rendered diagnostics, and `bayan-check` exits 0 or 1 within the timeout. A mutation in the Bayan port that makes an unconstrained integer literal `i64`, or that drops the second pass of the integer-literal inference, makes the proof fail.

## Open questions

Numbered after 009's Q151. Each records the conservative choice 010 takes; the handoff gets them in T23.

- Q152 Coverage: the self-hosted sources need a subset (no `Owned<T>`, `Untrusted`, typestate, `requires` rules, `stackalloc`, panic handlers or `context`), and binding them is a milestone (R13, T16). The target is still every `diag/` golden, and L018 is enacted only when the pending list is empty. Conservative: the handoff row asks for every `diag/` golden, and a law over a subset would claim an equivalence that does not hold.
- Q153 What equivalence compares: the version-1 typed dump plus the rendered diagnostics, computed in process from the C# `Compilation` for every input, including inputs with errors. `bayan types` keeps printing nothing on error, the dump gains no expression types and no version bump, and bound-tree equivalence is left to 011's `--emit-c` comparison. Conservative: no CLI or dump-format change; the diagnostics cover what the binding dump does not.
- Q154 Build layout: one module of the lexer and parser library files plus `selfhost/semantics/*.byn`, assembled by the harness with `Compilation.Create`, as 009 Q143. Conservative: no `import` between `selfhost/` directories; spec 012 decides the package layout.
- Q155 Representation: symbol and type pools with id structs, interned structural type keys, scopes and member tables as `Map`s keyed by `Symbol` and id structs, side tables keyed by 009's node ids. Not `dyn ref` symbol hierarchies stored in fields, not `Owned<T>`. Conservative: matches 009's tree and 008 R5, needs no region rule, and spec 011 can index the same pools.
- Q156 Iteration order: the C# front end is made order-explicit where hash order reaches output, before the port (T1); the port never sorts to compensate. Conservative: one order, stated in C#, and L009 keeps holding.
- Q157 Parity: ported 1:1 by method and pass, including diagnostic suppression (`Hold`/`Release`, `_scratch`, `_firstPass`) and the first-pass rollback in `BindFunction`. Conservative: any change is a C# change first, ported after, so L018 never blocks a fix.
- Q158 Instantiation bound: 64 nested instantiations, BYN2840 once per site, only if T1 shows C# does not terminate. Conservative: no new diagnostic for a problem that does not exist, and none of the repository's programs nests generics more than a few levels (T1 records the deepest).
- Q159 Expression depth: 4,096 levels counted at `BindExpr` entry, BYN2841, only if T1 shows a C# stack overflow. The parser's BYN1070 is not widened to binary chains. Conservative: L017 and 009's goldens stay unchanged, and 4,096 is far above any real expression.
- Q160 Options: `IncludeTests` (from `.test.byn`) and the defaults; `Library` and `SkipOwnershipCheck` are not ported. Conservative: the `diag/` harness uses only `IncludeTests`; the others are for C# tooling until spec 012.
- Q161 Diagnostic shape: the lexer port's `Diagnostic` gains severity, related spans and a source index in 010, the change 009 Q151 deferred. If round 3 has made `error` contextual, severity is an enum; otherwise `isError: bool`. Conservative: one diagnostic type across the self-hosted compiler; L001 and L017 are re-run in the same change.
- Q162 Corpus: 10,000 inputs from a fixed xorshift seed, generated in the test: mutations of `diag/`, `typed/` and `run/` inputs that keep them parsing (renamed identifiers, swapped types, changed literals, deleted or duplicated statements, swapped arguments, `let`↔`var`, added or removed `move` and `try`), programs from `tests/Bayan.Tests/OwnershipGenerator.cs`, and nesting and instantiation depths that straddle R8's bounds. Conservative: deterministic, and every failing input is kept in `tmp/binder-corpus/`.
- Q163 Speed: at most 10 times the C# front end on the self-hosted sources, median of 5, skippable. Conservative: the bound specs 001 and 009 set.
- Q164 C# exceptions: an input on which the C# front end throws is a C# bug fixed first; the port has no counterpart of the throw. Conservative: the reference is always a diagnostic list, never a crash.
