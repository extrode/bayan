## Approach
Both features are passes in the C# compiler, inserted on the bound tree after binding and before `Lowerer.Lower` (`src/Bayan.Lowering/Lowerer.cs`), so every site maps to a source span and compiler-generated code (loop counters, desugared `try`, pattern tests) is never mutated or counted. Mutation (R1–R8) rewrites each candidate expression or statement into a `BoundMutantSwitch(id, original, mutants[])` node; the lowerer lowers it at statement level, `if (byn_mutant == id) { pre_m; t = m } else { pre_o; t = o }`, because `&&`, `||`, `try`, `??`, `switch` and patterns hoist a prelude through `CaptureExpr` (`Lowerer.cs:1068-1082`) and a C ternary would run both arms' preludes. Only when neither arm produced a prelude does `CEmitter` emit `(byn_mutant == id ? mutated : original)`. `byn_mutant` is read once at startup from `BAYAN_MUTANT` (0 = no mutant). Coverage (R9–R10) inserts `BoundProbe(id)` statements before each statement and wraps each condition in `BoundBranchProbe(id, cond)`; error paths are counted on the function's error-return edge in the lowered code, keyed by (function, variant), so a variant that reaches the caller through `try` propagation counts as well as one raised by `fail` (user, 2026-10-31). The detailed `--coverage` listing names the origin of each hit (the `fail` site, or the `try` it passed through). Counters are a static `uint64_t` array in the generated C. Each test process writes its own file `BAYAN_COVERAGE.<test index>` at exit; the runner merges them. A run without `--test` (the selfhost harness, `bayan mutate --binary`) writes `<BAYAN_COVERAGE>.<pid>`, and the caller merges every file matching the prefix. Before a run the caller deletes every existing `<BAYAN_COVERAGE>.*` file (the `bayan test` runner does the same for `BAYAN_COVERAGE.<test index>`), so stale files from an earlier run are never merged (user, 2026-10-31). The flush runs from normal return, `exit()`, and the panic path: `byn_panic` ends in `abort()` (`bayan-rt.c:88`), which skips `atexit`, so the runtime gains one new hook pointer `byn_cov_flush` (not the user-owned `byn_on_panic`, `bayan-rt.c:42`) called before `abort()`. A test the runner kills on timeout loses its counters: its contribution is **unknown (timed out)**, never "uncovered"; the report lists the test, and a line reached by no other test shows as unknown, not missed. Neither node exists unless its flag is set, so a normal build emits the same generated C as today. R11's scope is the generated C (user, 2026-10-31): the flush hook in `bayan-rt.c` does nothing unless coverage is on, and the runtime file gains a version line (`BYN_RUNTIME_VERSION`, new) bumped with every change, so a reviewer can tell when and why Debug binaries changed.

Alternatives rejected: mutating the lowered tree (loses source attribution, mutates generated code); mutating C text (cannot know types, so R4 fails); one rebuild per mutant (the problem); an interpreter (non-goal). Speed comes from three things: one build (R2), running only the tests that reach a mutant's site (the mutant-0 run records per-test site reach, the same probe machinery as coverage), and stopping at the first failing test per mutant. A site no test reaches is reported "survived (not reached)" without running anything. Test function bodies (`FunctionKind.Test`, `Lowerer.cs:22`) and harness-generated `main.byn` are never mutated. A mutant's identity is (file, line, column, operator, mutated text), because `literal` gives two mutants and `variant` may give several at one place (user decision 2026-10-31); generic instances share their template's sites. Numeric ids are per binary, and every consumer keys by identity through that binary's `sites.json`, because the selfhost harness builds one binary per distinct `main.byn` (`SelfhostSemanticsHarness.cs:31-32, 44`).

## Changes by area
- `src/Bayan.Syntax` — attributes on statements, for `@unobservable because "…"` (R7). Today attributes parse on declarations, interface members and error variants only (`Parser.cs:433, 946, 1474`); `ParseStatement` (`Parser.cs:2136`) gains an `@` case. Statement attributes have an allow-list that starts with `@unobservable` only; an attribute applies to the next statement only, and any other attribute in that position is BYN1069 (new). `@allow` is the likely next entry. A missing or empty reason is BYN8001, as for every `because`. A mark covers every mutant whose site lies inside the marked statement's span; an optional operator argument narrows it to one operator, `@unobservable(boundary) because "…"`. Marked mutants still run: a marked mutant that is killed, or a mark with no mutant inside it, is the R7 warning. The `because` clause reuses `ParseAttributes`' J6 handling (`Parser.cs:562`), and an empty or missing reason is a diagnostic. An unknown statement attribute stays an error.
- `src/Bayan.Semantics` — bind `@unobservable` to the statement span it covers; record it in `Compilation` for the mutator. No other semantic change.
- `src/Bayan.Testing` (new project, referenced by `Bayan.Cli` and the test harness) — `Mutator` (operator table, site map, R4/R5), `CoverageInstrumenter` (R9), `QualityReport` (R12 JSON, terminal summary, per-line listing), `Gates` (R13).
- `src/Bayan.Lowering` — lower `BoundMutantSwitch`, `BoundProbe`, `BoundBranchProbe` to `LMutantSwitch`/`LProbe` (every arm lowered with the same rules as the original).
- `src/Bayan.Backend.C` — emit the switch and probes; `byn_mutant` and the counter array; the exit writer. `src/runtime/bayan-rt.c` gains the `byn_cov_flush` hook pointer (null unless the generated C of an instrumented build sets it, so it does nothing otherwise) called before `abort()`, and a new `BYN_RUNTIME_VERSION` line (R11).
- `src/Bayan.Cli` — `bayan test --mutate`, `--coverage`, `--mutate --run '<cmd>'` and `bayan mutate --binary <exe> --sites <map.json> -- <cmd>` (R3, external mode for prebuilt binaries), the default one-line coverage summary (R17), `package.byn` `test: Tests { lines:, branches:, errorPaths:, mutation:, summary: }` (R13, R17). Nothing under `test:` is parsed today (`src/Bayan.Syntax/Packages/Manifest.cs:27` knows only the field name); the new fields are parsed, and `diffCoverage` is accepted and ignored (non-goal). `bayan test` builds with coverage probes by default in Debug, the normal test build, for the R17 summary; `summary: false` builds without them. `--sanitize` builds carry probes only with an explicit `--coverage` (user, 2026-10-31).
- `tests/Bayan.Tests` — selfhost harness gains a snapshot mode: build the `.byn` under test once with schemata, compute the C# oracle once, and record per run its program args, stdout, stderr and exit code; per mutant the replay runs the binary directly (no `dotnet test`: its startup plus the front end costs ~4–6 s, ~30% of a 20 s build, measured by Fable 2026-10-31) and compares all four. Tests that call `SelfhostParserTests.Run` directly (T2:318, T3:46, T5:42, T13:1374) or pass args (T10:124, T11:263) are recorded the same way (R14). The guard (`scripts/selfhost/guard.sh`) calls `bayan mutate --binary` over every site of the task's files instead of sampling 8.
- `tests/cases/` — `diag/` cases for the new diagnostics, `run/` cases for instrumented programs (R10 law), mutation goldens (site map + report) per operator.
- `docs/bayan-spec.md`, `docs/bayan-grammar.md` — changed only through revision `docs/revisions/0014-test-tooling.md` (accepted 2026-10-31; T17 applies it): §20 operator table, report format, `@unobservable` (the "not in v0.1" note removed), statement attributes; §19.2 `Tests` fields.
- `scripts/quality/` — C# wrappers: `coverage.sh` (coverlet), `mutate.sh` (Stryker, `--mutate` scoped to the task's changed files), each converting to the R12 JSON (R15).

## Data / interfaces
- Mutation operators v1 (each a separate mutant, chosen by the operand type so every emitted mutant type-checks, R4): relational boundary (`<`↔`<=`, `>`↔`>=`), relational negation (`==`↔`!=`, `<`↔`>=`, `>`↔`<=`), logical (`&&`↔`||`), condition negation (`if c` → `if !c`, also `unless`, `while`, do-while, switch guards, `stmt if c`), boolean literal flip, arithmetic (`+`↔`-`, `*`↔`/`, `%`→`*`), integer literal ±1, unary minus removal, statement removal (void call, assignment, compound assignment), return of the type's empty value where one exists, error variant swap in `fail E.a` to another variant of E with the same payload type. A candidate whose operator does not apply to the type is counted "not emitted" (R4). The mutator cannot see every type error a mutant causes (a literal inside an already-folded constant, removing a statement that moves a value), so lowering (T5) re-binds and ownership-checks each mutant's enclosing statement; a failure is counted "not emitted" (user decision 2026-10-31).
- Site map (`<binary>.sites.json`): `{ version: 1, sites: [{ id, file, line, column, operator, original, mutated, unobservable?: reason }] }`.
- Report (`bayan-quality.json`, one schema for Bayan and C#, R12/R15): `{ version: 1, kind: "mutation"|"coverage", tool, timing: { build_s, mean_mutant_s, max_mutant_s, total_s, mutant_share_of_build }, files: [{ path, lines: {covered, total, missed: [n]}, branches: {...}, errorPaths: [{function, variant, hit}], mutants: [{site, status: killed|survived|timeout|marked|not_reached, killedBy?, suggestion?}] }], totals, operators: { name: {killed, survived, ...} } }`.
- Per-line listing: `<file>.cov.txt` / terminal listing with `+`/`-`/`~` gutter (R12).
- Environment: `BAYAN_MUTANT=<id>`, `BAYAN_COVERAGE=<path>`, `BAYAN_SITE_REACH=<path>` (mutant-0 reach recording).
- Coverage counter file (T9): a `--coverage` process with `BAYAN_COVERAGE` set writes `<BAYAN_COVERAGE>.<test index>` under `--test`, else `<BAYAN_COVERAGE>.<pid>`, on return from main, `exit()` or panic. Text, one line `bayan-coverage 1`, then `<counter id> <hits>` per counter hit at least once (an unlisted counter was not hit). Counter ids index the build's counter list (`CoverageInstrumenter.Instrument`): `line`, `branch` (one counter per outcome) or `error` (function, variant, origin `fail`/`try`/`catch`), each with file, line and column. The caller deletes stale `<BAYAN_COVERAGE>.*` files before a run (`CoverageInstrumenter.DeleteStale`).
- Baseline (spec Q5): `tests/quality-baseline.json`, per task file, written by `land.sh` when a task lands and checked by the guard: coverage and mutation score may not drop (spec goal "neither may regress").

## Risks & mitigations
- **Schemata change semantics of the original arm** (evaluation order, double evaluation). Mitigation: each arm is lowered independently and only one runs; law test "mutant 0 behaves as the plain build" runs all `tests/cases/run/` under a schemata build.
- **C compile time of a schemata build** grows with mutant count. Estimate (Fable, 2026-10-31): plain build 20.4 s of which C compile ~14 s; schemata compile 20–40 s once; per mutant 0.1–0.5 s (0.5–2.5% of a build); every site of one task file (300–800 sites) 1–3 min with reach filtering. Mitigation: measure on `selfhost/semantics` in the first task; if per-mutant share >10% the goal fails visibly (R8 reports it); fallback is per-file schemata builds.
- **Infinite-loop mutants.** Every mutant run has a timeout (max(1 s, 5× the test's own time)); a timed-out mutant counts as **killed**, as Stryker does, and is reported on its own line (R3).
- **Counter flush on panic/exit paths** may be missed. Mitigation: flush in the runtime's panic and exit paths, plus `atexit`; a `run/` case covers each exit path.
- **Stryker on .NET 10 and run time over `src/` (~32k lines).** Mitigation: scope to changed files per task; verify Stryker 5.0.0 supports `net10.0` in the first C# task, else report and ask.
- **No external input, auth or network** is involved; reports are local files. `BAYAN_COVERAGE`/`BAYAN_SITE_REACH` are user-supplied output paths, treated like `-o`. `BAYAN_MUTANT` is parsed as an integer; any other value means no mutant.
- **Self-hosted compiler.** These passes live in the C# compiler until self-hosting is done (user, 2026-10-31); the self-hosted compiler gets them after self-hosting, and spec 011 says so when it is written. The self-hosted *code* is mutation-tested and covered now, through the C# compiler.

## Decisions (user, 2026-10-31)
1. Self-hosted compiler: C#-only until self-hosting is done; spec 011 records the later port.
2. R11 covers the generated C; the runtime file is versioned.
3. Error paths: a variant passing through `try` counts as covered; the detailed report names the origin.
4. Default coverage summary in Debug builds; `--sanitize` only with `--coverage`.
5. Spec and grammar text through revision 0014; every example type-first with the `because "…"` clause.
6. Statement attributes: allow-list starting with `@unobservable`; next statement only; others BYN1069; a mark covers all its statement's mutants unless an operator argument narrows it.
7. Timed-out test: coverage unknown (timed out), not uncovered. Timed-out mutant: killed.
