## Problem

The handoff's "Road to self-hosting" row 012 is the last: a driver (`check`, `build`, `run`) written in Bayan, and the bootstrap. The finish line (handoff, "Road to self-hosting") says the Bayan compiler does `lex`, `parse`, `check`, `build` (with `--emit-c`) and `run`; stage 2's generated C is byte-identical to stage 3's; the full golden suite passes against the Bayan-built compiler; and `bootstrap/bayan.c` is committed. `new`, `init`, `test`, the cache and `--json` stay in the C# CLI.

Specs 001 and 009–011 leave four tools (`bayan-lex`, `bayan-parse`, `bayan-check`, `bayan-emit`), each a `main.byn` over the library files of the directories before it, assembled by a test harness with `Compilation.Create`. Each deferred the package layout to 012 (009 Q143, 010 Q154, 011 Q167). Neither `bayan build` nor any Bayan program can build that set today: a directory is one module (`Compilation.FromPath`, `Compilation.cs:63-73`, non-recursive `ModuleFiles` at `:111-115`), and imports resolve under the entry's directory, so the compiler's sources, spread over four directories with no imports between them, are not one input either compiler accepts.

The C# driver is `src/Bayan.Cli/CliApp.cs` (820 lines at `d462122`) with `Messages.cs` (203), `TerminalStyle.cs` (86) and `Progress.cs` (95), and it builds through `src/Bayan.Backend.C/Toolchain.cs` (428) and `Targets.cs` (48). The commands in the finish line use about 450 of those lines: dispatch and global options (`CliApp.cs:37-97`, `:296-334`), `Lex`, `Parse`, `Types` (`:99-138`), `ParseBuildOptions` (`:142-231`), `Compile` (`:241-272`), `Report` (`:279-290`), `Check`, `Build`, `Failed`, `ProgramName`, `RunProgram`, `Start` (`:403-535`), and `TryReadSingleFile` (`:804-819`); and from `Toolchain.cs`, compiler discovery (`:82-92`), the mode flags (`:197-203`) and the compile step (`:263-281`). Three things the C# driver does have no Bayan builtin: reading an environment variable (`BAYAN_CC`, `BAYAN_CACHE`, `TMPDIR`), knowing the current directory (`Path.GetFullPath`, which puts absolute paths in every rendered diagnostic, `DiagnosticRenderer.cs:51`), and creating a directory. The runtime (`src/runtime/bayan-rt.{h,c}`) is embedded in the C# compiler as resources (`Toolchain.cs:34-36`); a Bayan compiler has no resources.

## Goals

- `bayan`, built from `selfhost/bayan/` in round-3 syntax, runs `lex`, `parse`, `types`, `check`, `build` (with `--emit-c` and `-o`) and `run` on files, directories and scripts with the same stdout, stderr and exit code as the C# CLI.
- Stage 1 (the Bayan compiler built by the C# compiler) builds itself into stage 2, and stage 2 into stage 3; stages 2 and 3 emit byte-identical C for the compiler's own sources, in safe and in debug.
- The golden suite passes against stage 2 for every golden kind the Bayan compiler's commands cover.
- `bootstrap/bayan.c` is committed, and a C compiler plus `src/runtime/` builds a working Bayan compiler from it.
- A change that breaks the fixpoint, the suite against stage 2 or the committed C fails the normal test run and names the stage, the mode and the first differing line.

## Non-goals

- Retiring or freezing the C# compiler (self-hosting phase 5). It stays the reference for L001 and L017–L019 and the only compiler for the commands below.
- `new`, `init`, `test`, `dist`, `cache`, `clean`, `doctor`, `explain`, `fmt`, `audit`, `features`, projects (`package.byn`), `--diagnostics json`, `--target`, `-v`, the build cache and the script cache (handoff "Finish line"; Q179).
- Colour, the progress line and terminal-width wrapping (Q187).
- Windows as a bootstrap host; stages run on macOS and Linux (Q186).
- Porting the runtime, or any change to emitted C beyond what T1's builtins need (011 Q168).
- Changing any ported line of `selfhost/lexer/`, `parser/`, `semantics/` or `backend/` beyond the file moves of R8 and T1's builtin entries (Q178).

## User stories

- As a Bayan user without .NET, I want to build the compiler from `bootstrap/bayan.c` with a C compiler, so that Bayan builds from source.
- As a compiler developer, I want stage 2 and stage 3 to emit the same C, so that a miscompilation of the compiler by itself cannot hide.
- As a compiler developer, I want every golden that the Bayan compiler can run to pass against stage 2, so that "self-hosted" means the same behaviour, not just the same text for one input.
- As a user moving between the two compilers, I want `bayan check`, `build` and `run` to print the same thing from either, so that switching is invisible.
- As a maintainer, I want a test to fail when `bootstrap/bayan.c` is stale, so that the committed C always builds today's compiler.

## Requirements

- R1 Driver. `selfhost/bayan/main.byn` is the entry of `bayan`. Commands: `lex <file>|-` (`--json` is refused, R3), `parse [--ast] <file>`, `types <path>`, `check <path>`, `build <path>` with `--mode`, `-o`, `--emit-c`, `--all` and `-- <args>`, `run <path>` with `--mode`, `--all` and `-- <args>`, `version`/`--version`, and `help`/`--help`/`-h`; global `--color auto|always|never` (also `--color=…`) and `--ascii` as `TakeGlobalOptions` (`CliApp.cs:296-334`). `<path>` is a file, a directory (the whole directory is the entry module) or a script (a file starting with `#!`, compiled alone), as `Compile` (`CliApp.cs:264-267`); with no path, `.` when it holds `package.byn` (which R3 then refuses). Exit codes are `CliApp`'s: 0 ok, 1 failure, 2 usage, 4 toolchain.
- R2 Equivalence. For every invocation R1 accepts, stdout, stderr and the exit code equal `CliApp.Run` with both streams redirected (`Terminal(false, false, 0)`), `NO_COLOR=1`, the same arguments and working directory, after masking seconds to `0.00s` as the `style/` goldens do, except: `help` and a bare `bayan` print the driver's own usage, and `version` prints `bayan <Version> (selfhost)` with `Version` equal to `CliApp.Version`.
- R3 Refusals. A command or option outside R1 (`new`, `test`, `--target`, `--diagnostics json`, `-v`, a script run without a command, …) and a directory holding `package.byn` print one line `error: \`<what>\` is not available in the self-hosted compiler; use the C# \`bayan\`` to stderr and exit 2, before reading any source.
- R4 Paths. Relative paths are made absolute against `Io.currentDir()` and normalized as `Path.GetFullPath` does for `.`, `..` and repeated separators, so rendered diagnostics, `ProgramName` (`CliApp.cs:490-497`) and the `byn_file_` table match C# byte for byte. Symlinks are not resolved, as in .NET.
- R5 Toolchain. The C compiler is `$BAYAN_CC` split on spaces, else `zig cc`, else the first of `cc`, `clang`, `gcc` that starts, as `FindCompiler` (`Toolchain.cs:82-92`); none found prints `Toolchain`'s message and exits 4. Flags and mode flags are `Toolchain.cs:197-203` with `-I <dir> <dir>/main.c <dir>/bayan-rt.c -o <output>` and `-lm`, where `<dir>` is a fresh scratch directory (Q183); a failed compile prints `Messages.ToolchainError` with the compiler's output and exits 4. There is no cache: every `build` and `run` compiles. `build` without `-o` writes `Targets.ExecutableName(ProgramName)` in the current directory, as C# does outside a project.
- R6 Run. `run` builds into the scratch directory, starts the program through `Io.run` with the arguments after `--`, writes the captured stdout then stderr to its own, and exits with the program's code (`128 + n` for a signal, as `byn_io_run`); stdin is inherited (Q185).
- R7 Builtins. The C# compiler, the runtime, the spec (§13) and the ported checker and emitter gain three `Io` builtins, each with a `run/` golden: `Io.env(name: string) -> string?` (`uses env`; `null` when unset), `Io.currentDir() -> string fails IoError` (`uses fs`) and `Io.createDir(path: string) fails IoError` (`uses fs`; creates missing parents, succeeds when the directory exists). Nothing else is added to the language or the runtime (Q181).
- R8 Layout. The self-hosted compiler is one module in one directory, `selfhost/bayan/`: every library file of `selfhost/{lexer,parser,semantics,backend}/` moved in with its directory as a prefix (`lexer-tokens.byn`, `parser-parser.byn`, …), plus the driver's files (`main.byn`, `driver-*.byn`). The four tool entries move to `selfhost/tools/{lex,parse,check,emit}.byn`, and each harness builds `selfhost/bayan/*.byn` without `main.byn` and `driver-*.byn`, plus its tool file. No moved file changes; L001, L017, L018 and L019 pass after the move, and their law files name the new paths (Q178).
- R9 Runtime text. `selfhost/bayan/driver-runtime.byn` holds `runtimeHeader` and `runtimeSource`, two `const` strings equal to `src/runtime/bayan-rt.h` and `bayan-rt.c` byte for byte. It is generated, rewritten under `BAYAN_UPDATE=1`, and a test fails when it differs from `src/runtime/` (Q184).
- R10 Stages. Stage 1 is `bayan build selfhost/bayan --mode safe -o <stage1>` run by the C# CLI; stage 2 is `<stage1> build selfhost/bayan --mode safe -o <stage2>`; stage 3 is the same run by stage 2. With `C0` the C# `EmitC` of `selfhost/bayan` and `Cn` the output of `<stage n> build --emit-c selfhost/bayan`, `C0`, `C1`, `C2` and `C3` are byte-identical, in safe and in debug (Q182).
- R11 Golden suite against stage 2. Stage 2 passes: every `lex/` golden (`lex <case>` equals `.tokens`), every `parse/` golden (`parse --ast <case>` equals `.ast`), every `typed/` golden (`types <case>` equals `.types`), every `diag/` case (`check --all <case>` gives the stderr and exit code of the C# CLI for the same command, as R2; `DiagTests` ties that text to the `.diag` golden), and every `run/` case not named `*.test.byn` (`build --mode <mode> -o <exe> <case>`, then the executable with its `.args` and `.stdin` gives `.stdout`, `.stderr` and `.exitcode`, as `RunTests.Execute`). Other kinds stay with the C# CLI (Q188).
- R12 Bootstrap C. `bootstrap/bayan.c` is `C0` in safe mode. A test fails when it differs from `C0`, and `BAYAN_UPDATE=1` rewrites it. `bootstrap/README.md` gives the one command that builds it with a C11 compiler and `src/runtime/`, and a test builds it that way and checks that the result's `build --emit-c selfhost/bayan` prints `bootstrap/bayan.c` (Q189).
- R13 Checks in the suite. The normal test run builds stage 1, 2 and 3 once per test process and runs R10, R11 and R12 (Q190). A failure names the stage, the mode or golden case, and the first differing line of each side with its line number.
- R14 Driver checks. The normal test run runs stage 1 against `CliApp.Run` (R2) on: every `diag/`, `typed/` and non-`.test.byn` `run/` case with `check`, `types` and `build --emit-c`; a file, a directory, a script, a missing path, an unknown option, a refused command, stdin for `lex`, and `run` of `tests/cases/run/hello.byn` (or round 3's rename) with arguments after `--`. Until a command is ported its rows are listed in `tests/Bayan.Tests/selfhost-driver-pending.txt`; a listed row that passes fails the run, so the list only shrinks.
- R15 Source. Round-3 syntax (spec and GRAMMAR on this branch): no semicolons, name-first bindings and fields, `->` returns, `@` attributes, particles, `length` for sizes; `bayan fmt --check selfhost/bayan selfhost/tools` changes nothing. The driver's `Io.run` arguments that come from the command line are wrapped and trusted with `trustUnchecked() because "…"` as round 3's BYN2786 requires.

## Acceptance criteria

- Given `selfhost/bayan/`, when the C# CLI builds stage 1, stage 1 builds stage 2 and stage 2 builds stage 3, then `build --emit-c selfhost/bayan` prints the same bytes from all three and from `CliApp.EmitC`, in safe and in debug.
- Given stage 2, then every `lex/`, `parse/`, `typed/` and `diag/` case and every non-`.test.byn` `run/` case passes as R11 says.
- Given `bootstrap/bayan.c` and `src/runtime/`, when `cc -std=c11 -fwrapv -ffp-contract=off -O2 -DBYN_NDEBUG -I src/runtime bootstrap/bayan.c src/runtime/bayan-rt.c -o bayan -lm` runs, then `./bayan build --emit-c selfhost/bayan` prints `bootstrap/bayan.c`.
- Given a change to any `selfhost/bayan/*.byn` that changes `C0`, then the bootstrap-C test fails until `BAYAN_UPDATE=1` rewrites `bootstrap/bayan.c`.
- Given a `tests/cases/diag/` case with an error, when stage 1 runs `check <case>` from the repository root, then stderr shows absolute `-->` paths, the footer and the `bayan explain` line exactly as the C# CLI, and the exit code is 1.
- Given a file with 25 errors, then `check` prints 20 and the `DiagCapped` line, and `check --all` prints 25, on both sides.
- Given `bayan build hello.byn` in a directory with no `package.byn`, then both compilers write `hello` (`hello.exe` on Windows) in the current directory and print the same summary after masking.
- Given `bayan run prog.byn -- a b` where `prog` prints its arguments and exits 3, then the Bayan driver prints the same text and exits 3.
- Given `bayan test x.test.byn`, `bayan build --target linux-x64 x.byn` or a project directory, then the Bayan driver prints R3's line and exits 2, and writes nothing.
- Given `BAYAN_CC=/nonexistent`, then both compilers print the same toolchain error and exit 4.
- Given `src/runtime/bayan-rt.c` changed and `driver-runtime.byn` not regenerated, then the runtime-text test fails naming the file.
- Given `Io.env("HOME")`, `Io.currentDir()` and `Io.createDir` of an existing and a nested new directory, then the `run/` goldens give the same output from the C# compiler and from stage 2.

## Law candidates

- L020 (property, proven like L001 and L017–L019): stage 2 and stage 3 of the bootstrap emit byte-identical C for `selfhost/bayan/` in safe and debug, equal to the C# compiler's `EmitC` of the same sources, and stage 2 passes every golden R11 lists. A mutation in the Bayan emitter that writes `Io.monotonicNanos()` into the header comment makes the proof fail, and so does one that escapes `\n` in string literals as `\\n` (by a stage mismatch or a stage-2 golden failure).

## Open questions

Numbered after 011's Q177. Each records the conservative choice 012 takes; the handoff gets them in T13.

- Q178 Layout: one directory `selfhost/bayan/`, files moved with a directory prefix and not edited, tool entries in `selfhost/tools/`. Not `import` between `selfhost/` directories (every cross-file name would need `public` and qualification), not a build manifest, not a CLI form that takes several directories. Conservative: no language, CLI or ported-code change, and both compilers build the compiler with the input form they already share.
- Q179 Command scope: `lex`, `parse`, `types`, `check`, `build`, `run`, `version`, `help`. `types` is added beyond the finish line because 010's dump already exists and it brings the `typed/` goldens into R11. Everything the finish line leaves in C# is refused with exit 2 (R3), including scripts run without a command. Conservative: one clear refusal instead of a partial command.
- Q180 Equivalence: stdout, stderr and exit code of `CliApp.Run` with redirected streams and `NO_COLOR=1`, seconds masked, usage and version text excepted. Conservative: the C# CLI stays the specification, compared in process, and no output format changes.
- Q181 New builtins: `Io.env`, `Io.currentDir` and `Io.createDir`, nothing more. No file copy, rename, delete or exists: `-o` goes straight to the C compiler, and existence is the error code of a read or `listDir`. Conservative: the least the driver cannot do without, each in C# first with a golden, then in 010's builtins and 011's emitter.
- Q182 Stages: built in safe mode with no cache; C compared in safe and debug (fast emits safe's text, 011 R6); executables are not compared, since a C compiler may embed paths or build ids. Conservative: the comparison the self-hosting doc asks for, on text the two modes can differ in.
- Q183 Scratch directory: `$BAYAN_CACHE/self/<n>/`, else `$TMPDIR/bayan-self/<n>/`, else `/tmp/bayan-self/<n>/`, where `<n>` is `Io.monotonicNanos()` in decimal, created with `Io.createDir` and not removed (no delete builtin); `bayan clean --cache` (C#) removes the first. Conservative: never writes inside the project or the user's cache layout `v1/`.
- Q184 Runtime: generated `const` strings in `selfhost/bayan/driver-runtime.byn`, checked against `src/runtime/` by a test; not read from disk at run time and not located beside the executable. Conservative: the driver needs no install layout, and `bootstrap/bayan.c` carries the runtime text it writes.
- Q185 `run` output: captured by `Io.run` and written after the program exits, stdout before stderr; stdin is inherited, so `.stdin` goldens work. Interleaving and live output are lost. Conservative: no streaming builtin; the C# `bayan run` stays the interactive one.
- Q186 Hosts: stages and R11 run on macOS and Linux. On Windows the bootstrap tests skip with a reason; `bayan.c` is not built there by the suite. Conservative: `byn_io_run`'s Windows path and `.exe` naming are untested by 012, and phase 5's "every platform" is a later spec.
- Q187 Style: output is always `Style.Plain`; `--color always` is accepted and prints plain, `--ascii` switches the symbols as C# does, and there is no progress line and no wrapping (no terminal query builtin). Conservative: R2 compares the redirected, uncoloured form, which is what scripts and CI see.
- Q188 Golden scope: `lex/`, `parse/`, `typed/`, `diag/` (through the C# CLI text, since `bayan check` renders paths and `.diag` goldens of single files do not) and non-`.test.byn` `run/` cases. `diag-json/`, `manifest/`, `new/`, `out/`, `style/` and `.test.byn` cases stay with C#; the `.test.byn` emission path is covered by L019. Conservative: "the full golden suite" read as every golden the Bayan compiler's commands produce.
- Q189 Bootstrap file: `C0` in safe mode, refreshed by `BAYAN_UPDATE=1` whenever the compiler's sources change, with a drift test rather than release-only updates; the runtime is not copied into `bootstrap/`. Conservative: the committed C is never stale, and by L020 equals stage 2's.
- Q190 Cost: the stage chain and R11 run in the normal test run, each stage built once per process. T11 records the time; if the chain exceeds 300 s on the reference machine, the stages move behind `Law=L020` and the bootstrap-C drift test (no C compile) stays in the normal run. Conservative: the fixpoint is checked on every run until it is shown too slow.
